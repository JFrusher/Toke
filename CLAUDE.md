# toke — Project Context

Browser-first, vector-based **variable data design studio**. Bind canvas elements to a relational
dataset, cycle live records, impose N-up onto print sheets, export press-ready vector PDF.
Everything runs client-side. Vercel is a static/SSR host and nothing more.

Source PRD: `scratch/PRD.md`. Where this file and the PRD disagree, **this file wins** — it records
decisions made after the PRD audit. Divergences are listed in §9.

---

## 1. Build & Dev Commands

```bash
npm install
npm run dev          # next dev --turbopack        → http://localhost:3000
npm run build        # next build
npm run start        # next start

npm run typecheck    # tsc --noEmit
npm run lint         # biome check .
npm run format       # biome check --write .

npm run test         # vitest run
npm run test:watch   # vitest
npm run test:e2e     # playwright test
npm run test:pdf     # vitest run --project=golden   (PDF golden-file suite)

npm run env:pull          # vercel env pull .env.local          (Development scope)
npm run env:pull:preview  # vercel env pull .env.local --environment=preview
npm run env:list          # vercel env ls
```

**Before any commit:** `npm run typecheck && npm run lint && npm run test`.
CI runs the same four gates plus `build` and `test:e2e`.

Package manager is **npm** (pnpm/bun are not installed). Node 24.x.

**Branching:** work branches off `staging`, never off `main`. `main` is production and deploys on
merge. Full model, environment mapping and release process in [DEVELOPMENT.md](DEVELOPMENT.md).

`.env.local` is generated by `env:pull`, is gitignored, and is never edited by hand or committed.
toke is entirely client-side — **no environment variable may ever hold a secret**, since every
`NEXT_PUBLIC_` value is inlined into the browser bundle.

## 2. Architecture

### 2.1 Runtime shape

```
main thread                    worker: db.worker.ts        worker: pdf.worker.ts
───────────                    ────────────────────        ─────────────────────
React + Fabric canvas   ⇄      sql.js (SQLite WASM)        pdf-lib + fontkit
zustand stores                 typed RPC envelope          receives plain scene
IndexedDB persistence          owns ALL SQL                graph + font bytes
```

Three hard rules:

1. **No SQL outside `db.worker.ts`.** UI calls typed RPC methods; the worker owns the database
   handle. Nothing else imports `sql.js`.
2. **No Fabric objects cross a worker boundary.** Serialise to a plain `SceneNode[]` scene graph
   first. Fabric instances are not structured-cloneable and carry the whole canvas by reference.
3. **One text-measurement path.** `engine/text/measure.ts` wraps fontkit and is the *only* place
   text dimensions are computed. Canvas auto-fit and PDF layout both call it. Never use
   `ctx.measureText` or Fabric's internal measurement for anything that affects layout — screen and
   print would silently disagree.

### 2.2 Directory map

```
src/
├─ app/
│  ├─ layout.tsx                  root layout, fonts, theme
│  └─ page.tsx                    studio shell (client boundary)
│
├─ components/
│  ├─ shell/                      AppShell, HeaderBar, ModeSwitcher, StatusBar
│  ├─ canvas/                     StudioCanvas, CanvasRulers, CanvasToolbar, Guides
│  ├─ data/                       DataGrid, CsvImportDialog, RecordSourcePanel, SqlConsole
│  ├─ inspector/                  InspectorPanel, TransformFields, TypographyPanel,
│  │                              TokenBindingPanel, AutoFitSettings
│  ├─ preview/                    CycleBar, RecordSearch, PreflightReport
│  ├─ imposition/                 ImpositionPanel, SheetPreview, ExportDialog
│  └─ ui/                         retuned Shadcn primitives — see §4.5
│
├─ engine/                        ← pure logic. No React, no DOM where avoidable.
│  ├─ units/                      point-based unit system + conversions
│  ├─ geometry/                   rects, transforms, matrix maths
│  ├─ imposition/                 solver, crop marks, tent fold, pagination
│  ├─ db/                         db.worker.ts, rpc.ts, schema.ts, csv.ts
│  ├─ text/                       measure.ts, fontLoader.ts, autoFit.ts
│  ├─ tokens/                     parser.ts, resolver.ts, formatters.ts
│  ├─ scene/                      fabric ⇄ SceneNode serialisation
│  ├─ pdf/                        pdf.worker.ts, renderers/, document.ts
│  ├─ persistence/                tokeFile.ts, autosave.ts, assetStore.ts
│  ├─ history/                    command stack (undo/redo)
│  └─ store/                      zustand: studio, data, canvas, imposition

└─ types/                         shared type declarations
```

`engine/` is the testable core. If logic can live there instead of in a component, it lives there.
There is **no `src/app/api/`** — see §9.

### 2.3 Data flow

```
CSV ──► db.worker ──► guests table
                          │
      Record Source query ▼             one design declares ONE source query.
      SELECT * FROM guests WHERE …      its rows ARE the print run: 1 row = 1 card.
                          │
                    rows: Row[]
                          │
   ┌──────────────────────┼──────────────────────┐
   ▼                      ▼                      ▼
Live Mode            Preflight              PDF Export
row[cursor]          all rows               all rows
   │                 → overflow report      → imposition → pages
   ▼
token resolver → column lookup on the current row (NOT a query)
   ▼
auto-fit (measure.ts) → Fabric render
```

Tokens are **column references against the current row**, resolved in memory. They do not execute
SQL. Per-token SQL exists only as the repeater escape hatch (v1.2) with a parent-row context stack.

## 3. Code Style

### TypeScript

- `strict: true`, plus `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`.
- **No `any`.** Use `unknown` and narrow. No non-null `!` except immediately after an explicit guard.
- Prefer discriminated unions over optional-field soup:
  ```ts
  type Binding =
    | { kind: 'static'; text: string }
    | { kind: 'token'; expression: string; fallback: string; autoFit: AutoFitConfig };
  ```
- Branded types for units — they prevent the entire class of mm/px/pt bugs:
  ```ts
  type Points = number & { readonly __brand: 'Points' };
  type Millimetres = number & { readonly __brand: 'Millimetres' };
  ```
- `type` over `interface` unless declaration merging is needed.
- Named exports only. No default exports.

### State (zustand)

- Four stores, split by lifetime, not by screen: `useStudioStore` (mode, cursor, selection),
  `useDataStore` (schema, record source, rows), `useCanvasStore` (scene graph, viewport),
  `useImpositionStore` (sheet config).
- **Always select narrowly.** `useStudioStore(s => s.mode)`, never `useStudioStore()` — the latter
  re-renders the component on every unrelated state change, which is fatal on a canvas.
- Actions are colocated in the store. Components never mutate state inline.
- Derived values are computed in selectors or plain functions, never stored.

### Errors

- Fallible engine functions return `Result<T, E>`, they do not throw:
  ```ts
  type Result<T, E = AppError> = { ok: true; value: T } | { ok: false; error: E };
  ```
  Reserve exceptions for genuine programmer error (failed invariants).
- Every `AppError` carries `{ code, message, hint?, objectId? }`. `objectId` is what makes the
  diagnostics panel able to focus the offending canvas object.
- **Never swallow an error silently.** Worker failures, SQL errors, font load failures and overflow
  conditions all surface in the diagnostics panel. An empty `catch` is a review rejection.

### Components

- Server Components by default; `'use client'` only where interaction genuinely requires it. The
  studio shell is a client boundary — push it as deep as practical.
- One component per file, named after the file.
- Props typed inline. No `React.FC`.
- Order: hooks → derived values → handlers → early returns → JSX.
- No business logic in components. It belongs in `engine/`.

### Testing

TDD. Test first, watch it fail, then implement.

- **Vitest** for `engine/` — the imposition solver, unit conversions, token parser/resolver,
  auto-fit and geometry are pure functions and must be near-exhaustively tested.
- **Golden files** for PDF output. Render a fixture, compare extracted page geometry, box values
  and text runs against a committed baseline. Do not diff raw PDF bytes — they are not stable.
- **Playwright** for the shell: import CSV → bind a token → cycle records → export.
- Component tests only where the component holds real logic.

## 4. Design System

> The studio is a **precision instrument for print production**, not a marketing surface. Every
> pixel of chrome competes with the artboard for the user's attention, and the artboard wins.

### 4.1 Paper-first, three-tier value structure

The artboard is the brightest object on screen and the only pure white. The pasteboard sits *darker*
than both artboard and panels — this is the prepress convention (InDesign, Illustrator) and it is
what keeps a white card legible against light chrome.

```css
--paper:            #FFFFFF;  /* artboard ONLY. Nothing else is pure white. */
--pasteboard:       #D8D2C6;  /* infinite workspace behind the artboard */
--panel:            #FAF8F4;  /* sidebars, header, bottom bar */
--panel-raised:     #FFFFFF;  /* inputs, popovers, menus */

--hairline:         #DED8CC;  /* decorative dividers — contrast-exempt */
--hairline-strong:  #C7BFB0;  /* emphasised dividers — still decorative */
--border-control:   #908A7F;  /* input/control boundaries — 3.23:1, WCAG 1.4.11 */

--ink:              #1A1815;  /* primary text          16.70:1 on panel */
--ink-muted:        #6B6459;  /* labels, secondary      5.51:1 */
--ink-subtle:       #766F64;  /* placeholder            4.68:1 */
--ink-disabled:     #9A9182;  /* disabled ONLY — exempt 2.93:1 */

--accent:           #1F3A5F;  /* deep ink-blue — STATE ONLY  10.83:1 */
--accent-weak:      #E6EBF2;
```

Neutrals are **warm** (yellow-shifted), never blue-grey slate. Warm chrome makes the artboard read
as paper; cool chrome makes it read as another panel.

**Two distinctions that are load-bearing, not pedantry** — P0.6 enforces both:

- `--ink-disabled` is for disabled controls *only*. WCAG exempts disabled text from contrast;
  placeholders are **not** exempt, so they use `--ink-subtle`. Reaching for `--ink-disabled`
  because something "should look faint" is how a product fails an audit.
- `--hairline*` are decorative and may sit below 3:1. Anything that defines the **boundary of a
  control** — input, checkbox, select — must use `--border-control`.

### 4.2 Colour is data

The accent is not decoration. In a variable-data tool, colour carries meaning, and spending it on
"primary button" wastes the one signal the user needs most.

| Token | Value | Means |
|---|---|---|
| `--bound` | `#1F3A5F` ink-blue | Object is token-bound |
| `--overflow` | `#A6401F` rust | Text overflows at minimum font size |
| `--conditional` | `#2F6B6B` teal | Conditional rule attached (v1.1) |
| `--ok` | `#3D6B4A` moss | Pre-flight clean |

Never reuse these four for anything decorative. Never introduce a fifth without deleting one.

### 4.3 Typography

- **UI:** IBM Plex Sans. **Mono:** IBM Plex Mono — SQL console, token syntax, all numeric fields.
- `font-variant-numeric: tabular-nums` on **every** measurement, coordinate and record counter.
  Digits that shift width while cycling records are unusable.
- Scale: `11 / 12 / 13 / 15 / 18 / 24`px. 13px is the body default. Nothing between 18 and 24.
- Weights: 400, 500, 600 only.
- Labels are sentence case, not Title Case. No ALL-CAPS except unit suffixes (`MM`, `PT`).

### 4.4 Geometry & density

- Radii: **2px** controls, **4px** panels/dialogs. Never above 4px. `rounded-2xl` is banned.
- Borders: 1px hairlines. Separation comes from hairlines and value steps, never from shadow.
  The **one** permitted shadow in the product is the artboard's drop shadow.
- Spacing: strict 4px grid.
- Control height 28px, compact 24px. Input padding 6px/8px.
- Icons: Lucide at 14px/16px, `stroke-width: 1.5`.

### 4.5 Retuning Shadcn

Shadcn primitives ship as **starting points**, never as-is. Every component added must have its
height, type scale, radius, border, padding, focus ring and hover/active/disabled states brought
onto the scale above before it lands. A component that still looks like the docs example has not
been finished. Focus ring: 2px `--accent`, 1px offset, on every interactive element.

### 4.6 Motion

- Transitions only on `background-color`, `border-color`, `color`, `opacity`. 120ms, `ease-out`.
- **No transform animations on hover.** No `hover:scale-*`. No spring, no bounce.
- No scroll-triggered animation anywhere.
- Canvas manipulation is direct and immediate — it never animates.
- `prefers-reduced-motion: reduce` disables all of the above.

### 4.7 Accessibility — committed, not aspirational

- WCAG 2.2 AA contrast throughout. Verify the warm neutrals; they are easy to get wrong.
- Full keyboard operation of header, sidebars, inspector, data grid and SQL console.
- **Canvas keyboard access:** `Tab` cycles objects, arrows nudge (1pt; `Shift` 10pt), `Enter` edits
  text, `Escape` deselects.
- The layers tree is the screen-reader-navigable representation of canvas structure. It must stay
  in sync with the canvas — it is not decorative.
- Never signal state through colour alone. Overflow shows a badge *and* a colour.
- Below 1024px: an explicit "open toke on a larger screen" state with a read-only proof preview.
  Do not attempt to reflow the four-pane studio onto a phone.

### 4.8 Banned — AI-isms

Reject in review, without discussion:

1. Purple/indigo gradients, neon glows, radial spotlights, dark-mode-drenched layouts.
2. Gradient accent words, ✨ emoji decoration, three-word hero headlines.
3. Glassmorphism — `backdrop-blur` + translucent white borders.
4. Centred three-column icon/title/blurb feature grids.
5. Bento grids used decoratively where a table or list reads faster.
6. Blurred blob backgrounds, mesh gradients, `animate-pulse` ambience.
7. Floating 3D shapes, chrome spheres, abstract node-network art.
8. Uniform large radii — `rounded-2xl`/`rounded-3xl` on everything.
9. Marketing hype: "supercharge", "unleash", "seamless", "next-gen". Use print and database terms.
10. `hover:scale-105` and friends on every element.
11. Flat blue-grey `slate-50…900` monochrome palettes.
12. Centred hero with "Get Started Free →" + "Watch Demo ▶".
13. Fake client logo marquees.
14. Sticky bottom upgrade banners.
15. Decorative code windows with macOS traffic-light dots.
16. SVG wave/skew/zigzag section dividers.
17. Testimonial cards with circular avatars and five stars.
18. Decorative sparklines and area charts where a number or table is clearer.
19. Stock unstyled Shadcn/Radix — see §4.5.
20. Gradient badge pills: "🚀 Announcing v2.0 →".

**Write copy like a print professional.** "Bleed 3mm", "10-up on A4", "Trim 85 × 55mm",
"142 records, 15 sheets". Not "Create stunning designs effortlessly".

## 5. Domain Glossary

| Term | Meaning |
|---|---|
| **Record Source** | The one query per design whose rows define the print run. 1 row = 1 card. |
| **Token** | `{{ table.field \| formatter }}` — a column reference resolved against the current row. |
| **Auto-fit** | Shrink / truncate / wrap text to a bounding box, measured via fontkit. |
| **Imposition** | Arranging N designs onto a print sheet with bleed and crop marks. |
| **Trim** | Final cut size (e.g. 85 × 55mm). |
| **Bleed** | Artwork extending past trim (3mm default) to absorb cutting drift. |
| **Shared cut** | Neighbouring cards butt together on one cut line. Maximises yield. |
| **Tent fold** | Card printed at double height, folded to stand (85 × 110 → 85 × 55). |
| **N-up** | Count of designs per sheet. |
| **Pre-flight** | Pre-export scan reporting overflow, missing data and missing assets. |

## 6. Units

**Everything internal is `Points`** (1pt = 1/72 inch). Convert only at the edges:

- **Input** (user types mm/in) → convert to Points immediately on entry.
- **Display** → format from Points into the user's chosen unit at render.
- **Canvas** → Points × zoom = screen px. Zoom is a view transform, never baked into geometry.
- **PDF** → pdf-lib is natively in points. No conversion.

`1mm = 2.834645669…pt`. Use `engine/units`, never a literal. Branded types make a raw `number`
crossing into geometry a compile error.

## 7. Version Pins

`next@16` · `react@19` · `fabric@6.9.1` · `zustand@5` · `@tanstack/react-virtual` ·
`sql.js@1.14` · `pdf-lib@1.17.1` + `@pdf-lib/fontkit` · `papaparse` · `biome` · `vitest` ·
`@playwright/test`

Notes:
- **Fabric 6.9.1, not 7.x.** 6.x is what the documentation and community examples target.
- **No `@tanstack/react-table`.** Dropped after building the grid: the columns come from runtime
  schema introspection and the only behaviours are sort and inline edit, so a headless table model
  earned nothing over `[...rows].sort()`. `@tanstack/react-virtual` stays — virtualisation is
  genuinely non-trivial.
- **No component library for dialogs.** Native `<dialog>` + `showModal()` already provides focus
  trapping, Escape-to-close, `aria-modal` and an inert background, which are the only hard parts.
- **`pdf-lib` is effectively unmaintained** (1.17.1 is ~4 years old). Accepted deliberately: we use
  it as a low-level PDF writer, not a renderer, and our own renderer sits on top. Keep the
  dependency surface narrow so it stays replaceable.

## 8. Non-Goals (v1)

Repeaters/seating charts · conditional visibility · visual query builder · stress-test filters ·
duplex/back sides · arbitrary user tables · rich text (mixed styles in one text object) ·
ICC/PDF-X colour management · text shaping for complex scripts · auth · cloud sync · mobile layout.

Several are scheduled for v1.1–v1.3. None should be speculatively designed for now — except the
`.toke` file format, which is versioned from day one and must accommodate multiple designs per
project.

## 9. Deliberate Divergences from the PRD

| PRD | Here | Why |
|---|---|---|
| COOP/COEP `require-corp` headers (§9.1) | **Removed** | Only needed for `SharedArrayBuffer`. `sql.js` doesn't use it. Keeping them silently breaks every cross-origin font and image for zero benefit. |
| `src/app/api/` route stubs (§7) | **Removed** | Contradicts Axiom 1 (zero-server). Nothing would go in it. |
| pdf-lib "converts SVG/vector layers" (§6.3) | **Custom renderer** | pdf-lib cannot import SVG or canvas output. `SceneNode` → pdf-lib draw calls is hand-written; its supported feature set is a hard product constraint. |
| "CMYK-aware" (Axiom 3) | **RGB output in v1** | No ICC embedding, image conversion, overprint or PDF/X conformance is achievable client-side. Print shops convert. CMYK colour *values* are a v1.1 option. |
| Per-token SQL (§4.1) | **Column refs on the record-source row** | ~1,800 worker round-trips per export vs one query per design. Per-token SQL returns as the repeater escape hatch. |
| Auto-fit via `ctx.measureText` (§4.2.1) | **fontkit metrics** | Canvas and PDF must agree, or auto-fit passes on screen and overflows in print. |
| Dark `#121214` + indigo `#6366F1` (§2.1) | **Paper-first light** | The PRD palette is three of the banned AI-isms. See §4.1. |
| Inter + JetBrains Mono (§2.1) | **IBM Plex Sans + Mono** | Inter/JBM is the default AI-dashboard pairing. Plex is built for technical interfaces. Inter remains available as a *canvas* font for user designs. |
| Next 14 / React 18 / Fabric 6-rc2 / zustand 4 | **Next 16 / React 19 / Fabric 6.9.1 / zustand 5** | PRD pinned a release candidate and multiple stale majors. |
| No persistence specified | **IndexedDB autosave + `.toke` export** | The PRD's design loses all work on refresh. |
| No undo/redo specified | **Command-stack history, v1** | Non-negotiable in a design tool. |
| No test strategy | **Vitest + Playwright + golden files** | See §3. |
